# GSC-TEP Payload Model

## Conceptual Scientific Cargo for GSC-TEP

Intended location: `docs/design/gsc_tep_payload_model.md`

---

## 1. Purpose

This document describes the conceptual scientific payload expected inside a GSC-TEP.

This is not:

* a JSON schema
* a SQL schema
* a file-format specification
* an implementation contract

This is a scientific payload model.

It answers:

```text
What scientific cargo should a GSC-TEP carry?
```

and:

```text
Why is each component necessary?
```

---

## 2. Payload Identity

A GSC-TEP payload should represent a release-scoped semantic-prior package emitted by GSC.

The core biological identity represented by GSC is:

```text
(phenotype, gene)
```

The transportable release-scoped identity is:

```text
(gsc_release_id, phenotype, gene)
```

This identity must remain distinct from:

* sample-gene identity in RDGP
* variant identity in VAP
* canonical identity in VDB
* transport identity in TEP

A `tep_id` identifies the transport object. It does not replace GSC biological identity.

---

## 3. Conceptual Payload Entities

### 3.1 Semantic Prior Entity

The central payload entity is the semantic prior.

A semantic prior represents:

```text
a phenotype-scoped evidence-supported gene prior generated by GSC
```

Required scientific meaning:

* this gene has evidence relevant to this phenotype
* the evidence was aggregated by GSC
* the evidence belongs to a specific release
* the evidence is scored under a defined profile
* the evidence remains reusable downstream

Why necessary:

This is the primary scientific cargo of GSC-TEP.

---

### 3.2 Phenotype Entity

The phenotype entity defines the context in which a gene prior is meaningful.

Payload should preserve:

* phenotype identifier
* phenotype label
* phenotype profile
* phenotype version or release context, if available
* phenotype grouping or scope notes, if emitted by GSC

Why necessary:

Gene evidence is not phenotype-neutral. Removing phenotype context corrupts the meaning of the prior.

---

### 3.3 Gene Identity Entity

The gene identity entity preserves GSC-submitted gene identity.

Payload should preserve:

* source gene symbol
* source gene identifier
* source namespace
* normalized GSC gene symbol, if available
* GSC mapping status
* unresolved or ambiguous state

Why necessary:

VDB may later broker identity additively, but GSC-submitted identity must remain recoverable for audit and historical reproducibility.

---

### 3.4 Release Entity

The release entity identifies the GSC semantic-prior package.

Payload should preserve:

* `gsc_release_id`
* GSC version
* release label
* source package identity
* source release identifiers
* GSC run identity, if emitted
* generation context

Why necessary:

Semantic priors are release-bound. A phenotype-gene score from one release must not be silently treated as equivalent to another.

---

### 3.5 Score Entity

The score entity preserves quantitative evidence support.

Payload should preserve:

* consensus score
* semantic consensus score
* weighted source sum
* active score
* source count
* score interpretation context
* score nullability state

Why necessary:

Scores are biologically meaningful only when preserved with profile and source context. A score alone is insufficient.

---

### 3.6 Scoring Profile Entity

The scoring profile entity defines how scores should be interpreted.

Payload should preserve:

* scoring profile name
* scoring profile version
* scoring framework
* active scoring mode
* semantic-channel model
* score interpretation assumptions

Why necessary:

A score without its profile is not reproducible or interpretable.

---

### 3.7 Semantic Channel Entity

The semantic channel entity preserves the composition of evidence meaning.

Payload should preserve channels such as:

* direct disease evidence
* clinical interpretation evidence
* contextual biology evidence
* utilization evidence
* exploratory evidence
* convergence evidence
* annotation-only evidence

Each channel should preserve whether it was:

* scoring-active
* annotation-only
* absent
* unknown
* not applicable

Why necessary:

Semantic channels answer what kind of evidence supports a prior. This prevents false equivalence between direct disease evidence and weak indirect support.

---

### 3.8 Source Contribution Entity

The source contribution entity preserves which sources contributed evidence.

Payload should preserve:

* source ID
* source name
* source type
* source tier
* source semantics
* source release
* whether source contributed to score
* source contribution class
* source artifact reference
* source provenance context

Why necessary:

Future users must be able to reconstruct whether a prior was supported by one strong source, many weak sources, or multiple semantically distinct sources.

---

### 3.9 Provenance Entity

The provenance entity preserves origin and transformation context.

Payload should preserve:

* source artifact provenance
* GSC release provenance
* aggregation provenance
* scoring provenance
* rule/config provenance
* source ownership
* field lineage where available

Why necessary:

Without provenance, semantic priors cannot be audited, reproduced, or trusted.

---

### 3.10 Aggregation Topology Entity

The aggregation topology entity preserves relationships among sources, genes, phenotypes, and scores.

Payload should preserve:

* phenotype-to-gene relationship
* source-to-gene relationship
* source-to-channel relationship
* source-to-score relationship
* release-to-prior relationship
* prior-to-provenance relationship

Why necessary:

GSC meaning is relational. A flattened table cannot preserve why a consensus exists.

---

### 3.11 Uncertainty Entity

The uncertainty entity preserves ambiguity, absence, and conflict.

Payload should distinguish:

* unknown
* missing
* unresolved
* ambiguous
* not applicable
* zero support
* no match
* conflict
* annotation only

Why necessary:

Uncertainty is itself scientific information. It must not be represented only through omission.

---

### 3.12 Ontology Context Entity

The ontology context entity preserves phenotype and gene interpretation context.

Payload may preserve:

* phenotype namespace
* phenotype label
* phenotype mapping status
* gene namespace
* gene mapping status
* source ontology identifiers where available
* ontology version or mapping context

Why necessary:

Future ontology systems may reinterpret phenotype and gene relationships. Preserving original context protects historical meaning.

---

### 3.13 Source Artifact Manifest Entity

The source artifact manifest entity identifies artifacts used to generate transported evidence.

Payload or envelope-adjacent manifest should preserve:

* GSC output artifacts
* contributing source artifacts
* source artifact identities
* checksums or provenance references where applicable
* field lineage
* release package context

Why necessary:

A future user should be able to reconstruct which evidence surfaces produced the transported semantic prior.

---

## 4. Payload Multiplicity Requirements

GSC-TEP payload must preserve multiplicity across:

```text
phenotypes
genes
sources
semantic channels
releases
scoring profiles
source artifacts
ontology mappings
uncertainty states
```

Multiplicity must not be collapsed for convenience.

---

## 5. Payload Anti-Patterns

A GSC-TEP payload is scientifically inadequate if it contains only:

```text
gene_id
score
```

or:

```text
gene_symbol
phenotype
membership
```

or:

```text
gene_id
binary_flag
```

These structures destroy semantic prior meaning.

---

## 6. Downstream Consumer Requirements

A future RDGP consumer should be able to ask:

```text
For this sample-gene row, what phenotype-scoped GSC prior exists?
```

and then determine:

* which phenotype the prior belongs to
* which release generated it
* which score is active
* which semantic channels contributed
* which sources supported it
* what uncertainty exists
* whether the evidence is direct, contextual, exploratory, or utilization-based

---

## 7. Scientific Cargo Summary

A complete GSC-TEP scientific payload should carry:

```text
Semantic prior entities
Phenotype entities
Gene identity entities
Release entities
Score entities
Scoring profile entities
Semantic channel entities
Source contribution entities
Provenance entities
Aggregation topology entities
Uncertainty entities
Ontology context entities
Source artifact manifest entities
```

The goal is not to transport a small file.

The goal is to transport enough scientific meaning that GSC evidence remains alive inside VDB.
