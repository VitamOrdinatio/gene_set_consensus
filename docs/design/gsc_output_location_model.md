# GSC Output Location Model

## Purpose

This document defines the canonical output locations used by GSC and establishes the producer-owned artifacts that should be considered authoritative inputs for future GSC-TEP construction.

The purpose of this document is to answer:

```text
Where does GSC write its source-truth outputs?

Which outputs should future GSC-TEP construction consume?
```

This document does not define TEP structure.

This document defines producer output ownership and output location conventions.

---

# Core Principle

GSC-TEP construction must be derived from authoritative producer outputs.

GSC-TEP construction must not be derived from:

```text
validation snapshots
comparison artifacts
manual analysis files
historical exploratory outputs
```

unless explicitly designated as source artifacts.

---

# Canonical Output Layout

GSC producer outputs are organized into two primary output domains.

---

## Semantic Output Artifacts

Canonical location:

```text
results/tables/<gsc_release_id>/
```

Purpose:

```text
producer-owned semantic outputs
```

Expected artifacts:

```text
consensus_gene_set.tsv
gene_frequency_table.tsv
gene_provenance.tsv
gene_source_matrix.tsv
```

These artifacts represent the primary semantic outputs generated by GSC.

For future GSC-TEP construction, this directory should be treated as the canonical semantic evidence source.

---

## Validation and Provenance Artifacts

Canonical location:

```text
results/reports/<gsc_release_id>/
```

Purpose:

```text
validation context
execution context
release context
provenance context
```

Expected artifacts:

```text
run_manifest.yaml
output_contract_validation.tsv
validation_report.md
```

These artifacts provide supporting validation and provenance information that may be incorporated into future source artifact manifests and transport provenance records.

---

# Non-Canonical Locations

The following locations should not currently be treated as primary GSC source truth.

---

## Validation Comparison Artifacts

Example:

```text
docs/validation/comparisons/
```

Purpose:

```text
reproducibility evaluation
comparison analysis
historical validation
```

These artifacts are important for validation and auditing.

They are not canonical semantic outputs.

---

## Release Documentation

Example:

```text
docs/releases/
```

Purpose:

```text
human-readable release communication
release notes
release summaries
```

Release documentation is authoritative for release communication.

It is not the authoritative semantic substrate used for GSC-TEP construction.

# TEP Construction Inputs

Future GSC-TEP generation should consume:

```text
results/tables/<gsc_release_id>/*
```

as primary semantic inputs.

Future GSC-TEP generation may additionally consume:

```text
results/reports/<gsc_release_id>/*
```

for:

```text
release identity
validation context
provenance context
manifest generation
```

---

# Producer Ownership Model

GSC remains authoritative for:

```text
semantic prior generation
consensus scoring
semantic channel assignment
source aggregation
release generation
```

The artifacts located within:

```text
results/tables/<gsc_release_id>/
```

represent the producer-owned semantic outputs from which future transport artifacts should be derived.

# Summary

For current GSC development, the canonical producer output model is:

```text
results/tables/<gsc_release_id>/
    = semantic source truth

results/reports/<gsc_release_id>/
    = validation and provenance context
```

The May 11 semantic experimental packages currently represent the strongest candidates for generating the first real-world GSC-TEPs.

Future GSC-TEP construction should be derived from these producer-owned artifacts rather than from validation comparison outputs or release documentation.
